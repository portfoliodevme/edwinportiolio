Project overview

Explanatory

The project groups customers according to their transaction behaviour using unsupervised machine learning. Each customer is described by features that summarise how they transact, and K-Means clustering groups customers who behave in similar ways.

The purpose is to discover behavioural patterns and identify unusual groups that may be useful during fraud investigation. The resulting groups can be reviewed through an interface built for the project.

Clustering does not prove fraud

The clustering system does not prove that a customer is fraudulent. It identifies behavioural groups and unusual patterns that can be investigated further. Human investigators make the final judgement.

Problem statement

Explanatory

Banks process large volumes of transactions, and identifying behavioural patterns in them by hand is difficult. Investigators cannot examine every customer one by one.

Customers also transact in very different ways. Unsupervised clustering can help by discovering groups of customers with similar behavioural characteristics. It needs no labelled examples of fraud, and it gives investigators a structured starting point for deciding where to look first.

Methodology

Explanatory

The work follows nine stages, each feeding the next.

  1. 1

    Dataset

    The transaction records as obtained from the source, before any changes are made.

  2. 2

    Data cleaning

    Remove duplicate or invalid records, correct data types and deal with missing values so that later steps work on reliable input.

  3. 3

    Feature engineering

    Summarise each customer's transactions into measures of behaviour, such as how often and how much the customer transacts. Each customer becomes one row of features.

  4. 4

    Preprocessing

    Prepare the features for modelling, for example by reshaping heavily skewed values so that a few very large ones do not dominate the result.

  5. 5

    Feature scaling

    Put all features on a comparable scale. K-Means relies on distance, so a feature measured in large numbers would otherwise outweigh the others.

  6. 6

    K-Means clustering

    Group customers into a chosen number of clusters, so that customers in the same cluster are close together in feature space.

  7. 7

    Cluster evaluation

    Check how well separated and compact the clusters are, and use this to support the choice of the number of clusters.

  8. 8

    Visualisation

    Plot the clusters and their sizes so that the groups can be seen and compared.

  9. 9

    Behavioural analysis

    Describe each cluster by the typical feature values of its customers, in plain language, and flag groups that differ markedly from the rest for investigators to review.

K-Means clustering

Explanatory
What K-Means is
K-Means is an unsupervised algorithm that splits data into k groups, called clusters. It needs no labels. It looks only at how close the data points are to each other.
Why it suits this project
Fraud examples are rare and often unlabelled, so a method that works without labels fits the problem. K-Means is also simple to explain, quick to run on many customers, and gives clusters that can be described by their average behaviour.
Customers as feature vectors
Each customer is represented by a list of numbers, one per feature, such as transaction count or average amount. This list is the customer's feature vector, and it places the customer at a point in feature space.
Centroids and assignment
The algorithm starts with k initial centroids. Each customer is assigned to the nearest centroid, measured by Euclidean distance. Each centroid is then moved to the mean of the feature vectors assigned to it. These two steps repeat until the assignments stop changing or an iteration limit is reached.centroid = mean of all feature vectors in the cluster
Interpreting the final clusters
Once the clusters are fixed, each centroid is read as the typical customer of its cluster. Comparing centroids and cluster sizes shows which groups are common, which are small, and which behave very differently from the rest.

Choosing the number of clusters

Explanatory

K-Means needs the number of clusters, k, to be chosen before it runs. Two common ways to support that choice are described below.

Elbow method

Run K-Means for a range of k values and plot the total within-cluster distance (inertia) for each. The distance always falls as k grows, but the improvement slows down. The point where the curve bends, the elbow, suggests a sensible k.

Silhouette score

For each customer, compare the average distance to the others in its own cluster with the average distance to the nearest other cluster. Scores run from -1 to 1, and higher values mean better separated clusters. The k with the highest average score is preferred.

Limitations

Explanatory
  • There are no fraud labels, so the project cannot report a fraud detection rate or accuracy. Clusters are leads for investigation only.
  • K-Means works best with compact, roughly round clusters and can struggle with other shapes.
  • Results depend on the features chosen, how they were scaled, and the number of clusters selected.
  • Outliers can pull centroids away from typical behaviour, and results can vary with the initial centroids.
  • An unusual cluster can contain legitimate customers, and fraud can sit inside an ordinary-looking cluster.
